# Go Algorithms & Engineering Patterns

Практическая коллекция алгоритмов и инженерных паттернов на Go, которую можно использовать как **справочник, учебный материал и набор готовых примеров для подготовки к техническим собеседованиям**.

Проект показывает не только реализацию алгоритмов, но и то, как применять их при решении реальных задач: ограничении нагрузки, параллельной обработке, работе с графами, поиске, сортировке и безопасных финансовых операциях.

## Что вы получите от проекта

Этот репозиторий поможет:

* разобраться, как реализуются ключевые алгоритмы на Go;
* увидеть алгоритмы не только в теории, но и в работающем коде;
* быстро найти готовый пример нужного алгоритма;
* изучить работу с `goroutine`, `channel`, `map`, `slice` и синхронизацией;
* понять, как выбирать алгоритм под конкретную задачу;
* подготовиться к алгоритмическим задачам на технических собеседованиях;
* использовать примеры как основу для собственных решений;
* сравнивать рекурсивные и итеративные подходы;
* изучать оценку сложности алгоритмов и ограничения реализации.

## Алгоритмы и задачи

### Поиск и сортировка

* **Binary Search** — поиск элемента за `O(log n)`.
* **Quick Sort** — быстрая сортировка массива на месте.
* **Merge Sort** — сортировка методом «разделяй и властвуй».

Эти примеры позволяют разобраться в базовых алгоритмах поиска и сортировки, рекурсии, разбиении задачи на подзадачи и оценке сложности.

### Работа с графами

* **BFS** — обход графа по уровням.
* **BFS Shortest Path** — поиск кратчайшего пути в невзвешенном графе.
* **DFS Recursive** — рекурсивный поиск в глубину.
* **DFS Iterative** — поиск в глубину через стек без рекурсии.

На этих примерах можно понять, как выбирать между BFS и DFS, работать со списками смежности, отслеживать посещённые вершины и восстанавливать найденный маршрут.

### Структуры данных

* **Singly Linked List** — односвязный список.
* **In-place Reverse** — разворот списка без создания дополнительной структуры данных.
* **Two Pointers** — техника двух указателей.
* **Sliding Window** — техника скользящего окна.

Эти реализации помогают понять работу со ссылками, указателями, срезами и алгоритмами, позволяющими уменьшить дополнительные затраты памяти.

### Конкурентность и производительность

**Worker Pool**

Пример параллельной обработки задач с использованием нескольких goroutine и каналов.

Можно изучить:

* распределение задач между worker'ами;
* передачу данных через `channel`;
* синхронизацию завершения работы;
* ограничение количества одновременно выполняемых операций.

**Rate Limiter / Token Bucket**

Реализация алгоритма ограничения частоты запросов с поддержкой кратковременных всплесков нагрузки.

Пример полезен для понимания:

* rate limiting;
* token bucket;
* потокобезопасности;
* работы с большим количеством goroutine;
* контроля нагрузки без создания отдельного таймера на каждый запрос.

### Финансовые операции

**Account Transfer**

Пример реализации перевода денежных средств между счетами.

Задача демонстрирует практические принципы финансовых расчётов:

* использование `int64` вместо `float32/float64`;
* хранение денег в минимальных денежных единицах;
* проверку некорректных сумм;
* проверку достаточности баланса;
* изменение состояния двух счетов в рамках одной операции.

Такой пример полезен для понимания того, почему финансовая логика требует особого подхода к точности и валидации данных.

```text

```

Это позволяет изучать каждую реализацию независимо от остальных.

## Как использовать репозиторий

Репозиторий можно использовать несколькими способами:

1. **Для обучения** — выбрать алгоритм и разобрать его реализацию.
2. **Для подготовки к собеседованию** — повторить классические алгоритмические задачи.
3. **Как справочник** — найти пример конкретной техники или структуры данных.
4. **Для практики Go** — изучать алгоритмы одновременно с goroutine, channel, map, slice и другими возможностями языка.
5. **Для собственных проектов** — использовать реализации как отправную точку для решения прикладных задач.


Проект развивается постепенно: новые алгоритмы и инженерные задачи могут добавляться по мере необходимости.
