# Алгоритмы Golang

## Алгоритм: Token Bucket (Корзина токенов)
Это «золотой стандарт» индустрии.
Есть «корзина», в которую с постоянной скоростью добавляются токены (разрешения на запрос).
У корзины есть максимальная вместимость (burst).
Когда приходит запрос, мы пытаемся забрать один токен.
Если токен есть — выполняем запрос. Если нет — ждем или возвращаем ошибку.

Решение задачи в файле `cmd/rate_limiter/rate_limiter.go`

## Реализация Rate Limiter (Token Bucket)
Необходимо реализовать механизм, который пропускает не более запросов в секунду, но при этом позволяет кратковременные «всплески» (bursts) трафика.
Требования:
Потокобезопасность: Алгоритм должен корректно работать при обращении из тысяч горутин.
Эффективность: Нельзя создавать по таймеру на каждый запрос.
Гибкость: Возможность динамически проверять, можно ли выполнить операцию прямо сейчас.

Решение задачи в файле `cmd/rate_limiter_token_bucket/rate_limiter_token_bucket.go`

## Задача: Бинарный поиск

Правила:
Если target существует в массиве, функция должна вернуть его индекс.
Если target отсутствует, функция должна вернуть -1.
Алгоритм должен иметь сложность по времени O(log n).

## Разработка ядра платежного модуля
Задача: «Разработка ядра платежного модуля»
Контекст:
Вы разрабатываете внутреннюю систему для обработки транзакций в финтех-стартапе. Система должна быть предельно точной и исключать потерю данных при расчетах.
Бизнес-требования:
Защита от потери точности: Программа должна исключать использование чисел с плавающей точкой (float32/64) при расчетах, так как это недопустимо в финансовых операциях. Все расчеты должны вестись в минимальных денежных единицах (копейках, центах).
Валидация: Система не должна позволять переводить отрицательные суммы или списывать больше средств, чем есть на балансе.
Атомарность (Логическая): Операция должна гарантировать, что если сумма списана с одного счета, она обязательно будет зачислена на другой.
Техническое задание:
Создать структуру Account, содержащую уникальный ID и баланс (в формате int64).
Реализовать функцию Transfer, которая принимает указатели на два счета и сумму перевода.
Функция должна возвращать ошибку, если:
Сумма перевода меньше или равна нулю.
На балансе отправителя недостаточно средств.
Написать демонстрационный сценарий (в main), который инициализирует два счета и выполняет успешный перевод дробной суммы (например, 150.50 руб.), отображая состояние «до» и «после».
Решение задачи в файле `cmd/account_transfer/account_transfer.go`

# Алгоритм обхода BFS
ТЗ: Базовый обход графа методом BFS
1. Цель
Реализовать алгоритм, который посещает все доступные узлы графа, начиная с заданной точки, в порядке их удаленности (по слоям).
2. Входные данные
Граф: Список смежности (какой узел с кем соединен).
Стартовая точка: Узел, с которого начинается обход.
3. Ключевые компоненты (Инструменты)
Очередь (Queue): Хранит узлы, которые мы уже увидели, но еще не успели «опросить» об их соседях. Работает по принципу: первым пришел — первым ушел.
Список посещенных (Visited): Черновик, куда мы записываем имена узлов, в которых уже побывали, чтобы не ходить по кругу (защита от бесконечного цикла).
4. Логика работы (Алгоритм)
Положить стартовый узел в очередь и пометить его как посещенный.
Пока очередь не пуста:
Достать первый узел из начала очереди.
Напечатать его имя (или выполнить другое действие).
Найти всех его соседей.
Если сосед еще не записан в списке посещенных:
Пометить его как посещенный.
Добавить его в конец очереди.
5. Ожидаемый результат
Программа должна вывести список всех узлов графа в порядке их «досягаемости»: сначала идут ближайшие соседи, затем соседи соседей и так далее.
Решение задачи в файле `/cmd/bfs/bfs.go`
